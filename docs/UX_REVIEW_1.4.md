# 1.5.0 查询结果筛选与词典折叠 Review

## 问题

1. 英文单词会同时产生 Cambridge、Collins、基础词典和翻译结果，长页面中无法快速只看某一来源。
2. 词典卡片只有“全文摘要/全部展开”两种状态，`run` 等长词条仍需要在大量词义中滚动。
3. 词性信息已经被解析，但没有用于导航；动词、名词、短语等内容仍混排在一张卡片内。
4. 原来的展开状态保存在单个 SwiftUI View 的临时 `@State` 中，切换筛选或查询下一个词后会丢失。
5. SwiftUI 重绘词典卡片时会重复调用正文结构解析器，长词条虽不读取整本词典，但仍有不必要的重复解析。

## 1.4.0 实现

### 结果来源快速筛选

结果区顶部新增横向筛选条：

- 全部
- Cambridge
- Collins
- 基础词典（命中时）
- 翻译
- 表达

每个筛选项显示当前结果数量。切换只改变当前展示，不会重新查询词典或调用网络。有效筛选会保存到 `UserDefaults`，后续查询在对应来源仍存在时继续沿用；来源不存在时自动回到“全部”，避免空白页面。

### 词典内部分类

`DictionarySenseGrouper` 把已解析的词义归入稳定类别：

- 动词
- 名词
- 形容词
- 副词
- 代词
- 介词
- 连词
- 限定词与数量词
- 感叹与交际用语
- 短语与固定搭配
- 习语
- 其他释义

分类保持原词典中第一次出现的顺序，同类词义合并展示，词义自身的原编号和语法标题不会丢失。

### 两级折叠

每本词典提供三层浏览粒度：

1. 整本词典卡片收起/展开。
2. 每个词性分类独立收起/展开。
3. 分类内“摘要/全部词义与例句”切换。

默认只展开第一类，每类先展示 2–3 个词义和每个释义前 2 个例句。卡片菜单支持展开所有分类、收起所有分类、展开全部内容和恢复默认摘要布局。

### 状态复用

展开状态使用“词典 ID + 分类 ID”作为稳定键保存：

```text
cambridge-en-zh::verb
collins-cobuild-en::noun
cambridge-en-zh::related-terms
```

因此用户把 Cambridge 的名词分类收起后，查询下一个单词仍保持相同阅读习惯。每本词典可单独恢复默认布局。

### 结构化结果缓存

查询命中后，`DictionaryPresentationParser` 在后台把正文转换成 `DictionaryPresentation`，结果保存到 `AppModel.dictionaryPresentations`。筛选、展开、收起和 SwiftUI 刷新都复用该结构，不再重复解析原始长文本。

## 保留的边界

- 筛选只影响展示，不改变词典查询顺序和翻译路由。
- 不增加全文搜索、历史数据库或复杂工作区。
- 不把 Cambridge 与 Collins 的释义合并成一个“综合词条”，以免丢失来源和原始结构。
- 不记忆某一个具体单词的滚动位置；只复用来源筛选和分类展开习惯。
