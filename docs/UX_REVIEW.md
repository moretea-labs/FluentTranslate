# 使用逻辑 Review（1.2.0）

## 原有问题

1. 源语言默认固定为中文，英文输入容易形成错误方向。
2. `TextEditor` 没有绑定 Return 主动作，鼠标点击成本高。
3. “默认翻译、准确翻译、指定服务、语气、优化表达”同时占据首层操作，用户在输入前就要理解内部架构。
4. 词典查询只有一个扁平翻译字符串，中文释义、英英定义和例句没有独立结构。
5. 每次执行都会继续追加主结果，连续查询后页面越来越长。
6. 缓存写入在翻译返回链路中同步重写整个文件，缓存变大后可能拖慢可见结果。
7. 已内置 Cambridge 双解和 Collins 英英的真实索引；固定个人词典无需每次导入。

## 1.2.0 的交互规则

| 输入 | 智能模式默认动作 |
|---|---|
| 中文词、短语或句子 | 中文 → 英文翻译 |
| 英文单词 | 查询已加载词典 + 英文 → 中文翻译 |
| 英文短语或句子 | 英文 → 中文翻译 |
| 日文、韩文等 | 翻译为中文 |

显式模式：

- **智能**：默认，自动判断。
- **查词**：只查询词典，不访问翻译服务。
- **翻译**：只翻译，可以手动设置语言。

键盘：

- `Return`：执行当前主动作。
- `Shift+Return`：换行。
- `Command+Return`：准确翻译。

## 结果层级

1. 词典查询：按已加载词典顺序展示，每本词典一张卡片。
2. 翻译结果：默认服务一张主卡片，主动调用其他服务后追加对比卡片。
3. 表达优化：只有选中翻译结果后才出现。

## 性能调整

- 本地词典同步查询，命中时不产生网络等待。
- 缓存持久化改为 180 ms 合并延迟的后台写入，不阻塞结果返回。
- MyMemory 默认超时由 10 秒降为 8 秒。
- 新请求通过 generation 标识忽略旧请求的迟到结果，避免界面被过期响应覆盖。
- 默认仍然只调用一个外部翻译服务，不并行竞速。

## 仍未完成

- 通用 MDX/MDD 动态导入仍不是当前个人使用版本的目标；现有两本词典采用预转换内存映射索引。
- 词典启用、排序和分组管理页面。
- 发音、词形变化和模糊建议。
- 全局快捷键及划词查询。

这些能力适合在当前主交互稳定后继续增加，不应重新把首屏变成复杂的服务控制台。
