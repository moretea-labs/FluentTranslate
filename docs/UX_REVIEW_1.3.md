# 1.3.0 词典排版与交互 Review

## 已发现的问题

1. MDX 导入结果被压成纯文本，词性、释义、翻译、例句和短语没有视觉层级。
2. 超长词条按字符数截断，容易在一个词义中间断开，也无法快速浏览不同词义。
3. Cambridge 长词条会在词义之间插入 Related Phrases/Idioms，旧逻辑可能把后续词义误归入短语。
4. 中英例句位于同一行时无法分别排版。
5. 输入框和主按钮同时注册 Return，macOS 下存在重复提交风险。
6. 修改输入后直接调用准确翻译，可能把新文本结果追加到旧查询中。
7. 重复点击同一服务或同一 AI 场景会持续堆叠重复卡片。
8. 结果位于输入区下方，查询后需要手动滚动；复制操作也没有反馈。

## 1.3.0 调整

- 新增 `DictionaryPresentationParser`，分别处理 Cambridge、Collins 和内置结构化词条。
- Cambridge 按编号词义、子词条、英文定义、中文释义、双语例句和相关短语分组。
- Collins 按重复语法标签拆分词义，并把释义和例句分层显示。
- 长词条默认展示 Cambridge 前 3 个词义、Collins 前 2 个词义，每个释义默认展示 2 个例句。
- 展开后显示全部词义和全部例句，不再按固定字符数粗暴截断。
- 中英同一行例句自动拆分成两行。
- 词典卡片增加英汉/英英标识、音标、词义数量、查询耗时、系统朗读和复制菜单。
- 删除主按钮的 Return 快捷键，仅由输入编辑器处理提交，避免双触发。
- 新增 `lastSubmittedText`，所有结果明确绑定到最后一次提交文本。
- 新输入直接调用准确翻译时清空旧结果；同一服务的新结果替换旧卡片。
- 相同 AI 场景、语气和服务的新结果更新旧卡片。
- 查询后自动滚动到结果；输入修改未提交时显示橙色提示。
- `Command+L` 聚焦并全选输入框；清空后自动回到输入框。
- 复制后显示短暂的“已复制到剪贴板”反馈。

## 暂不增加的功能

- 查询历史：个人使用目前不是主路径，增加数据库和管理界面会扩大复杂度。
- 通用 MDX/MDD 管理：当前两本固定词典已经满足需求，继续保留转换脚本即可。
- 原词典真人音频：缺少配套 MDD，当前使用 macOS 系统朗读作为稳定替代。
- WebView 原样渲染 MDX HTML：会重新引入 CSS、脚本、资源路径和安全问题；当前原生结构化排版更稳定。
